🏁 Why a graphics card? The great painting race

  
Both chips must paint the same 60×36-pixel picture. The CPU has a few powerful cores. The GPU has thousands of simple ones.

  

    
CPU vs GPU(slowed way down so you can see it)

    

      
CPU 8 big brainy cores 0.00 s

      
GPU 2,048 tiny cores 0.00 s

    

  


  

    
🧬
Same code, different input
Every pixel runs the exact same program. Only its position (and data) differ.

    
🙈
No peeking at neighbours
A pixel can't see what other pixels decided. That's what makes it so parallel.

    
🧠
No memory between frames
Shaders forget everything after each run. Time is passed in as a number.

    
🗣️
Special languages
GLSL (WebGL/OpenGL), HLSL (DirectX), MSL (Metal), WGSL (WebGPU).

LEVEL 05

    
Talking to shaders: in, out & uniform

    
Shaders can't read your variables. The CPU has to ship data to them — and there are exactly four delivery services.

  

  

    

      

        
        
        
        
        
      

    

    

  

  

    
📦
Attributesdifferent for every vertex
in vec3 a_position;
in vec3 a_normal;
in vec2 a_uv;
Position, normal, UV, colour… read straight from a buffer. Vertex shader only.

    
📢
Uniformssame for everyone this draw
uniform float u_time;
uniform mat4  u_model;
uniform vec3  u_lightDir;
Broadcast to every vertex and every pixel. Time, matrices, colours, settings.

    
🌈
Varyingsvertex → fragment, blended
// vertex shader
out vec3 v_color;
// fragment shader
in  vec3 v_color;
Vertex shader writes them per corner; the rasterizer interpolates them for each pixel.

    
🖼️
Texturesimages you can sample
uniform sampler2D u_tex;
vec4 c = texture(u_tex, uv);
Big arrays of data (usually pictures) that any shader can look up by coordinate.

LEVEL 10

    
Thinking in parallel: warps & branches

    
GPU cores march in squads of 32 (a warp on NVIDIA, a wavefront on AMD) that execute the same instruction at the same moment. That has a funny side effect on if statements…

  

  

    

      

      
    

    

      

      

        
0cycles
100%lanes busy

    

  

  
😴 Hiding the wait: why GPUs juggle many warps

  
Reading memory (like a texture) takes hundreds of cycles. Instead of waiting, the scheduler instantly switches to another warp that's ready.

  

    
grey = waiting for memory · colour = doing math

    
  

  

    
🚀
Do
Use math & built-ins like mix, step, smoothstep instead of if when you can.

    
🧮
Do
Compute once on the CPU what is the same for every pixel — send it as a uniform.

    
🐌
Avoid
Long loops, many texture reads per pixel, and branches that split neighbouring pixels.

    
📏
Remember
A 4K frame = 8.3M pixels. 10 extra instructions = 83M extra instructions per frame.

  







  

    
LEVEL 11

    
Raymarching: 3D worlds with zero triangles

    
Some shaders draw entire 3D scenes inside one fragment shader. Each pixel shoots a ray and asks a signed distance function (SDF): "how far is the nearest surface?" — then safely jumps that far. Repeat until you hit something.

  

  

    
Sphere tracing in 2Ddrag 👁 the eye and the 🎯 aim point

    

      
      

        
0steps taken

        
The coloured bands are the distance field: each band = same distance to the nearest shape. Blue = outside, orange = inside (negative distance).

        
Each circle is a "safe sphere": nothing is closer than its radius, so the ray can leap to its edge.

        
float d = sceneSDF(p);   // distance to nearest
if (d < 0.001) hit!
p += rayDir * d;         // jump safely

      

    

  

  

    

      The same idea in 3D — one fragment shader, no meshes

LEVEL 14

    
The shader family & their languages

    
Vertex and fragment shaders are the famous siblings. Modern GPUs have a whole family — each runs at a different point in the frame.

  

  

    
Vertex shaderruns per vertex
Moves corners: transforms, skinning, waves, wind in grass.
WebGLWebGPUVulkan/DX

    
Fragment / pixel shaderruns per pixel
Colours pixels: lighting, textures, materials. DirectX calls it a "pixel shader".
WebGLWebGPUVulkan/DX

    
Compute shaderruns per work item
General number crunching: particles, physics, AI, image processing, culling.
WebGLWebGPUVulkan/DX

    
Tessellation shadershull + domain
Split triangles into many smaller ones on the GPU — for detailed terrain & smooth curves.
WebGLWebGPUVulkan/DX

    
Geometry shaderruns per primitive
Can create or delete whole triangles (e.g. one point → a blade of grass). Mostly replaced by mesh shaders.
WebGLWebGPUVulkan/DX

    
Task & mesh shadersruns per meshlet
The modern way: a compute-style shader generates small chunks of geometry directly.
WebGLWebGPUVulkan/DX

    
Ray-tracing shadersray-gen · hit · miss
Shoot real rays through a scene: closest-hit shaders shade surfaces, miss shaders paint the sky.
WebGLWebGPUVulkan/DX

    
Visual shader graphsno typing required
Unity Shader Graph, Unreal Materials, Blender nodes — boxes & wires that compile to shader code.
