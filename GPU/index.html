      Meet the Computer

      Basic Before we meet the GPU, let’s meet its whole family!

      🧸 KID VERSIONA computer is like a busy house 🏠. There’s a thinker (CPU), a desk for today’s stuff (RAM), a bookshelf that remembers everything (SSD), a power plant (PSU), roads connecting every room (motherboard)… and a giant art studio full of painters — that’s me, the GPU!

      🏠 The family of parts

      Every part has one job. Together they turn your clicks into games, videos and AI answers. In the 3D lab, tap each part to meet it, then hit ▶ Play the data journey to watch a game picture get made.

      What happens when you press ▶ in a game?

      📚➡️📝
      Load

      The game is copied from the SSD bookshelf onto the RAM desk.

      🧠💭
      Think

      The CPU works out the rules: who moved? what got hit? what should be drawn?

      📋🛣️
      Send

      It sends a “to-draw list” to the GPU over the PCIe highway.

      🎨🎨🎨
      Paint

      The GPU’s thousands of cores color millions of pixels at once.

      🖥️😍
      Show

      The finished picture (a frame) zooms down the cable to your screen.

      …and this whole trip happens 60 to 240 times every second! 🤯

      🤓 Nerd corner GPU vs graphics card
      • The GPU is the chip. The graphics card is the whole board: GPU + its own memory (VRAM) + power parts + cooler + fans.
      • Integrated GPU: built into the same chip as the CPU (most laptops, phones, Macs). Discrete/dedicated GPU: a separate chip or card with its own memory (gaming PCs, data centers).
      • PCIe is the highway slot. PCIe 4.0 ×16 moves about 32 GB/s each way; PCIe 5.0 doubles it to about 64 GB/s.
      • A frame is one finished picture. FPS = frames per second.

      Remember

      • CPU = brain 🧠, GPU = army of painters 🎨.
      • RAM is fast but forgetful; SSD is slow but remembers.
      • Data travels SSD → RAM → CPU → GPU → screen.

      The Operating System

      Basic The boss who keeps every app (and the GPU) in line.

      🧸 KID VERSIONThe Operating System (OS) is like a school principal 🧑‍🏫. Apps are students who all want stuff: time with the teacher (CPU), a desk (memory), the art room (GPU). The principal makes a fair schedule so nobody fights and nobody breaks anything!

      🏢 The OS is a building with floors

      Apps live on the top floor. They can’t touch the hardware directly — they must ask the floors below. Each request travels down: app → libraries/APIs → kernel (the OS’s heart) → driver (translator) → hardware. Then the answer travels back up.

      Try the buttons in the 3D lab to send a request!

      🪟 Windows🍎 macOS🐧 Linux🤖 Android📱 iOS🎮 console OSes

      Basic

      😴CPU core
      Press an app to start!

      Each colored block = one tiny turn (in real life about 1–10 milliseconds). Too fast for humans to notice — so it feels like everything runs at once!

      🖱️✨
      Click!

      📁➡️📝
      Load

      The file system finds the app on the SSD; it’s copied into RAM.

      🤓 Nerd corner kernel & GPU scheduling
      • User mode vs kernel mode: apps run in a safe “user mode”. Only the kernel (and drivers) run in privileged “kernel mode”. Apps cross the wall with system calls.
      • Virtual memory: each app sees its own fake address space; page tables map it to real RAM. The GPU has its own MMU and page tables too.
      • Preemptive multitasking: a timer interrupt lets the kernel pause an app mid-task (a context switch) and run another.
      • GPU work is queued: apps record command buffers through an API (DirectX, Vulkan, Metal); the driver turns them into GPU machine code and the OS’s GPU scheduler time-slices the GPU between apps.

      Remember

      • The OS is the boss: time, memory, files, devices, safety.
      • Apps never touch the GPU directly — they go through the API → OS → driver.
      • “Running at once” is really super-fast turn-taking.

      CPU vs GPU

      Basic One genius… or a thousand helpers?

      🧸 KID VERSIONImagine 1,000 sheets of easy sums. Would you rather have 1 genius professor 👩‍🏫 or 1,000 kids 🧒 each doing one sheet? The kids finish way first — that’s a GPU! But for one super-tricky puzzle where each step needs the last one, the professor wins — that’s a CPU.
      👩‍🏫

      CPU

      A few big, clever cores. Great at decisions & step-by-step work.

      VS

      GPU

      Thousands of small, simple cores. Great at doing the same thing to lots of data.

      🧪 Try the 3D race

      🧱 Big repeated job: paint a 1,024-tile picture. The CPU’s 8 fast cores take turns. The GPU’s 1,024 small cores each paint one tile at the same time.

      🧩 Step-by-step puzzle: each step needs the answer of the step before. Now extra workers can’t help — the fast CPU core wins!

      🤓 Nerd corner Amdahl’s law

      GPUs only help with the part of a job that can be split up. Amdahl’s law: if 10% of a program must run step-by-step, the best possible speed-up is 10× — even with a million cores!

      • SIMD/SIMT: one instruction, many data — GPUs run one instruction on a whole team of threads.
      • CPUs also have small SIMD units (AVX, NEON), so they’re a little bit parallel too.
      • The real world uses both: the CPU organizes, the GPU crunches.

      Remember

      • CPU = few fast smart cores (low latency).
      • GPU = many simple cores (high throughput).
      • Lots of independent work → GPU. Step-by-step → CPU.

      Anatomy of a Graphics Card

      Intermediate Let’s take one apart (safely, in 3D!)

      🧸 KID VERSIONA graphics card is like a sandwich 🥪: a board in the middle with the GPU chip & its memory, a metal cooler on top to soak up heat, fans to blow the heat away, and a metal plate on the bottom. Slide the explode slider to pull it apart!

      👆 Tap a part (here or in 3D)

      🌡️ Why so much cooler?

      A big GPU can use 300–600 watts — like 5 old light bulbs squeezed into a postage stamp! All that energy turns into heat. Press 🔥 Show heat to watch it flow: chip → copper base → heat pipes → fins → fans → out.

      One high-end gaming chip (RTX 4090) packs about 76 billion transistors, 16,384 CUDA cores and 24 GB of VRAM moving about 1 TB of data per second.
      🤓 Nerd corner power, memory, binning
      • VRM phases: many small regulators take turns supplying ~1 volt at hundreds of amps — smoother, cooler power.
      • GDDR vs HBM: gaming cards place GDDR6/GDDR6X/GDDR7 chips around the GPU. Data-center GPUs (H100, B200) stack HBM memory towers right next to the chip on a silicon interposer for huge bandwidth.
      • Binning: chips with a few defects get some units switched off and are sold as cheaper models.
      • Thermal throttling: if the chip gets too hot, it lowers its clock speed to protect itself.
      • TGP/TBP: the total power the board is designed to draw.

      Remember

      • GPU chip in the middle, VRAM around it.
      • VRM feeds clean power; heatsink + fans remove heat.
      • PCIe fingers = road to the CPU; ports = road to the screen.

      Inside the GPU Chip

      Intermediate A whole city on a fingernail.

      🧸 KID VERSIONZoom into the chip and you find a city 🏙️: neighborhoods (GPCs), factories (SMs), and inside each factory, rows of workers (CUDA cores) plus special machines — Tensor cores for AI math and RT cores for light rays.

      CUDA cores

      🏭 Inside one SM (Streaming Multiprocessor)

      Each SM has 4 teams. Each team has a warp scheduler (the boss with a megaphone 📣), 32 CUDA-core lanes, a Tensor core, and a big register file (tiny super-fast lockers). The whole SM shares L1 / shared memory, texture units and an RT core.

      Switch the 3D lab to 🏭 One SM and watch warps fire!

      📣 Warps: teams of 32 that march together

      Threads are grouped into teams of 32 called a warp. One boss shouts one instruction — “add!” — and all 32 do it at the same time, each on its own number. This is called SIMT: Single Instruction, Multiple Threads.

      The clever trick: when a warp is waiting for data from memory, the scheduler instantly switches to another warp that’s ready. No time wasted! That’s called latency hiding.

      🤓 Nerd corner SM numbers
      • Ada Lovelace SM (RTX 40): 128 FP32 lanes, 4 Tensor cores, 1 RT core, 4 warp schedulers, 64K × 32-bit registers (256 KB), 128 KB L1/shared memory.
      • An SM can hold many warps at once (up to 48 on Ada). Occupancy = active warps ÷ max warps.
      • Other names: AMD says Compute Units and wavefronts (32 or 64 wide); Apple says GPU cores and SIMD-groups (32 wide); Intel says Xe-cores.
      • Fixed-function helpers live outside the SMs too: video encoders/decoders (NVENC/NVDEC), display engine, copy engines.

      Remember

      • Chip → GPCs → SMs → cores.
      • Warp = 32 threads doing the same instruction.
      • Tensor cores = AI math; RT cores = light rays.

      🧮 Matrices

      A 4×4 grid of numbers that can move, turn, scale and squish points in one multiply. Three of them — Model, View, Projection — carry each corner from “inside the object” to “on your screen”. Multiplying them is exactly the math GPUs (and AI chips) are built for.

      🖌️ Shaders

      Tiny programs the GPU runs thousands of times at the same time: the vertex shader once per corner, the pixel (fragment) shader once per pixel. Game artists write them to create water, fur, fire, toon outlines…

      🟥 Rasterization

      Turning triangles into pixels: test every pixel center, interpolate depth and texture position, keep only the nearest fragment with the depth buffer, then hand each one to the pixel shader.

      Vertex shader (GLSL) · once per corner 
      uniform mat4 model, view, projection;
in  vec3 position;   // e.g. (-1, -1, 1)
in  vec3 normal;
in  vec2 uv;
out vec3 vNormal;
out vec2 vUv;

void main() {
  vNormal = mat3(model) * normal;
  vUv     = uv;
  // ① model  ② view  ③ projection
  gl_Position = projection * view * model
              * vec4(position, 1.0);
}

      ↑ steps ①–④ of the slow-motion lab

      Fragment / pixel shader (GLSL) · once per pixel 
      uniform sampler2D tex;       // the picture to paint on
uniform vec3 lightDir;
in  vec3 vNormal;              // interpolated by the
in  vec2 vUv;                  // rasterizer!
out vec4 color;

void main() {
  vec3  base  = texture(tex, vUv).rgb;
  float light = max(dot(normalize(vNormal), lightDir), 0.0);
  color = vec4(base * (0.3 + 0.7 * light), 1.0);
}

      ⏱️ The frame budget

      To hit a frame rate, every frame must be finished in time. Pick a screen and speed:

      Rasterization vs ray tracing

      Most games rasterize (fast!) and add a sprinkle of ray tracing for reflections and shadows. RT cores speed up “does this ray hit a triangle?” checks. Upscaling (DLSS, FSR, XeSS, MetalFX) draws a smaller image and uses smart math or AI to fill in the details.

      🤓 Nerd corner shaders & buffers
      • Shaders are tiny programs run by thousands of threads: vertex shaders (per corner), pixel/fragment shaders (per pixel), compute shaders (anything).
      • Depth buffer (z-buffer): remembers how far each pixel is so near things hide far things.
      • Textures & mipmaps: pictures wrapped onto triangles, with pre-shrunk copies for far-away objects.
      • Draw call: one “please draw this” command from the CPU. Too many = CPU bottleneck.
      • Double buffering & V-Sync: draw the next frame while showing the current one, swap when the screen refreshes.
      • APIs: DirectX 12, Vulkan, Metal, OpenGL, WebGL/WebGPU (this page uses WebGL!).

      Remember

      • Vertices → triangles → pixels → shading → frame.
      • 60 FPS means each frame has just 16.7 ms.
      • Raster = fast, ray tracing = realistic.

      CUDA: Bossing the Army

      Advanced How programmers talk to thousands of GPU threads.

      🧸 KID VERSIONCUDA is NVIDIA’s way of bossing around the GPU army. You write instructions for ONE worker, then shout “Launch a million of these!” — and every worker does the same job on its own piece of data.

      📦 Grid → Blocks → Threads

      A launch makes a grid of blocks. Each block is a team of threads that can share fast memory and wait for each other. The GPU sends blocks to free SMs — in any order.

      In the 3D lab, press 🚀 Launch kernel, then switch to the big GPU. Same code — finishes way faster! That’s CUDA’s superpower: it scales automatically.

      CPU way 🐢 
      // one worker does every item, one by one
for (int i = 0; i < n; i++) {
    c[i] = a[i] + b[i];
}

      ↑ a million items = a million loop turns

      Python + PyTorch (uses CUDA for you) 🐍 
      import torch
a = torch.rand(1_000_000, device="cuda")
b = torch.rand(1_000_000, device="cuda")
c = a + b   # runs as a CUDA kernel on the GPU!
      CUDA way ⚡ 
      // write the job for ONE thread...
__global__ void add(float *a, float *b, float *c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];  // my item!
}

// ...then launch a million of them
int threads = 256;
int blocks  = (n + threads - 1) / threads;
add<<<blocks, threads>>>(d_a, d_b, d_c, n);

      ↑ every thread computes its own number i

      🤓 Nerd corner blocks & sync
      • Blocks must be independent — that’s why the hardware can run them in any order on any number of SMs.
      • Threads in a block share __shared__ memory and can wait for each other with __syncthreads().
      • Block size is usually a multiple of 32 (a warp), often 128–256.
      • Streams let copies and kernels overlap. Unified Memory (cudaMallocManaged) moves data automatically.
      • Always check errors and synchronize before timing — kernel launches are asynchronous!

      Remember

      • Kernel = a function every thread runs.
      • Grid of blocks of threads; blocks go to SMs.
      • Same code runs faster on a bigger GPU.

      Memory: Need for Speed

      Advanced The fastest worker is useless without ingredients.

      🧸 KID VERSIONWorkers need ingredients (data) to cook. In your hands = instant. In your backpack = quick. On the classroom shelf = a few steps. In the school library = a walk. Across town = a long bus ride! Run the 3D race to see the difference.
      LevelLike…SizeWait
      🟥 Registers✋ your hands~256 KB per SM~1 tick
      🟧 L1 / Shared🎒 backpack~128–256 KB per SM~30 ticks
      🟨 L2 cache🗄️ class shelf~50–100 MB~200 ticks
      🟩 VRAM🏫 school library8–192 GB~500 ticks
      🟦 CPU RAM🌉 across town16 GB–TBsway more (µs)

      “Ticks” are clock cycles (roughly 0.5 nanoseconds each). Numbers are approximate and vary by GPU.

      📏 Latency vs 🚰 bandwidth

      Latency = how long the pipe is (time for the first drop). Bandwidth = how wide the pipe is (how much flows per second). GPUs care most about wide pipes and hide the long wait by switching warps.

      🚰 How wide are the pipes? (memory bandwidth)

      Bar length uses a squished (square-root) scale so the small ones are still visible. GB/s = gigabytes per second. Approximate peak numbers.

      GDDR vs HBM: two ways to place memory

      🤓 Nerd corner the memory wall
      • GPU math speed has grown faster than memory speed — the memory wall. Many jobs are limited by bandwidth, not math.
      • Shared memory is a programmer-controlled scratchpad. Load a tile once, reuse it many times (tiling).
      • Bank conflicts: shared memory has 32 banks; if many threads hit the same bank, they queue up.
      • AI chatbots generating text read all their weights for every token — that’s why huge, fast memory (HBM) matters so much.

      Remember

      • Closer memory = faster but smaller.
      • Bandwidth (width) matters most for GPUs.
      • Crossing PCIe to CPU RAM is the slowest trip — avoid it!

      🎓 Training vs 💬 inference

      📚🔁
      Training

      Practice with the answer key. Guess → check → nudge the knobs. Billions of times. Thousands of GPUs, weeks.

      💬⚡
      Inference

      Using the trained brain to answer you. Fewer GPUs, needs to be fast.

      📏 Number precision (fewer bits = faster)

      ■ sign ■ exponent (size) ■ mantissa (detail). AI is happy with fewer details → 2–8× faster math & less memory.

      When one GPU isn’t enough

      📦📦📦
      Data parallel

      Every GPU has a full copy of the model, each learns from different examples, then they share notes.

      🧩🧩
      Tensor parallel

      Split each big matrix across GPUs; they work on pieces of the same layer.

      🏭➡️🏭
      Pipeline parallel

      GPU 1 does the first layers, GPU 2 the next… like a factory line.

      🔗⚡
      NVLink

      Super-fast cables between GPUs so they can share notes quickly.

      🤓 Nerd corner tensor cores & FLOPs
      • A Tensor core computes a small tile D = A×B + C every few clock cycles — dozens to hundreds of multiply-adds at once.
      • A transformer needs roughly 2 × parameters operations per token: a 70-billion-parameter model ≈ 140 billion operations per word piece.
      • Prefill (reading your prompt) is compute-bound; decode (writing one token at a time) is usually memory-bound.
      • FlashAttention keeps attention math in on-chip memory to avoid slow VRAM trips.
      • Quantization stores weights in 8 or 4 bits to fit bigger models and run faster.

      Remember

      • AI = huge piles of multiply-and-add = matrix multiplication.
      • GPUs compute all answer cells in parallel; Tensor cores do whole tiles.
      • Lower precision = faster + smaller.

      NVIDIA vs Apple Silicon

      Intermediate Two different ways to build a GPU — neither is “wrong”.

      🧸 KID VERSIONNVIDIA card: a giant art studio next door 🏭 with its own supply room. Super powerful, but supplies must be carried over a bridge. Apple Silicon: the art studio is inside the house 🏠 and everyone shares ONE big supply room — less carrying, less energy, but a smaller studio.

      🚚 Separate vs 🤝 shared memory

      Discrete GPU (NVIDIA card): CPU RAM and GPU VRAM are different places. Data must be copied over the PCIe bridge before the GPU can use it.

      Unified memory (Apple M-series): CPU, GPU and Neural Engine sit on one chip and read the same memory. No copying!

      Press the buttons in the 3D lab to compare data trips, power and memory size.

      “Cores” mean different things! One NVIDIA CUDA core = one math lane. One Apple GPU core = a bundle of about 128 math lanes. So a 40-core Apple GPU has ~5,120 lanes. 🍎≠🍊

      Two ways to paint a frame

      🎮 Gaming PC / AI training

      Pick a discrete GPU (NVIDIA, or AMD Radeon). Most AI research code is written for CUDA first.

      💻 Laptop life & creators

      Apple Silicon: long battery, silent, big unified memory for photo/video and running local AI models.

      🏢 Data centers

      NVIDIA H100/B200-class, AMD Instinct, and AI chips like Google’s TPUs — thousands linked together.

      🤓 Nerd corner the lines are blurring
      • NVIDIA also builds unified designs: Grace Hopper superchips, Jetson robot boards and the DGX Spark desktop share memory between CPU and GPU.
      • Apple’s TBDR also does hidden surface removal before shading, so hidden pixels are never painted.
      • Unified memory removes copies, but a top discrete GPU still has more raw bandwidth and math.
      • Others: AMD (Radeon, Instinct, ROCm), Intel (Arc, Xe), phone GPUs like Qualcomm Adreno and Arm Mali — mostly tile-based too.

      Remember

      • NVIDIA card = separate studio + own memory + bridge.
      • Apple = all-in-one chip + shared unified memory.
      • Power & raw speed vs efficiency & simplicity.

      Pro Tips & Design Decisions

      Advanced The secrets of the people who build and program GPUs.

      🧸 KID VERSIONEven an army needs good habits: march together, grab supplies in one trip, and don’t make half the team wait. In the 3D lab, 32 little robots (one warp) show you the good and the bad way!

      🚚 Coalescing: one trip, not 32

      When 32 neighbors in a warp read neighboring memory, the GPU grabs it all in one big scoop. If they read random places, it needs many separate trips — way slower.

      🔀 Divergence: don’t split the team

      A warp shares one instruction. If half the team takes the if and half the else, the GPU runs both paths one after the other while each half waits. Same work, double time!

      ⚖️ Big design decisions (simple → deep)

      Simple

      Many small cores

      🐜 lots of simple cores
      ⚖️
      🦁 few smart cores

      GPUs pick throughput: tons of work per second, even if one task is slower.

      Simple

      Wide memory pipes

      🚰 huge bandwidth
      ⚖️
      ⏱️ low latency

      Wide buses and HBM feed thousands of cores; the wait is hidden by switching warps.

      Medium

      Threads instead of big caches

      🔁 swap warps while waiting
      ⚖️
      🗄️ giant caches

      Huge register files keep many warps “parked” so switching is free.

      Medium

      SIMT warps of 32

      💰 one control unit per 32 lanes
      ⚖️
      🔀 divergence cost

      Sharing instruction logic saves chip space and power — but branches hurt.

      Medium

      Special-purpose units

      ⚡ Tensor/RT/video cores
      ⚖️
      🧰 general cores

      Fixed-function hardware is 10× more efficient — but only for its one job.

      Medium

      Lower precision

      🏎️ FP8/FP4 speed
      ⚖️
      🎯 FP32/FP64 accuracy

      AI tolerates rounding; science simulations often don’t.

      Deep

      Discrete vs unified

      🏭 own VRAM, more power
      ⚖️
      🏠 shared memory, efficiency

      Copies over PCIe vs sharing one pool (Chapter 11).

      Deep

      Chiplets & links

      🧩 several dies + NVLink
      ⚖️
      🔲 one giant die

      Huge dies have more defects; data-center GPUs like B200 join two dies, and racks link many GPUs.

      Deep

      The power wall

      🔥 higher clocks
      ⚖️
      🔋 perf per watt

      Power grows fast with voltage and clock speed, so GPUs go wide-and-slower instead of narrow-and-fast.
