Chapter 7

How Wasm runs

A .wasm file goes from network bytes to running machine code in six steps. The browser overlaps the first few, so compiling finishes almost as soon as downloading does.

Six steps, from bytes to running

1 · Fetchdownload app.wasm
2 · Stream-compilecompile while downloading
3 · Validatesafety check, one pass
4 · Machine codeLiftoff: fast start
5 · Instantiateimports in, memory made
6 · Call & tier upJS calls exports
  1. Fetch. The page requests app.wasm like any other file. The server must label it application/wasm for streaming to work.
  2. Stream-compile. WebAssembly.instantiateStreaming() hands bytes to the engine as they arrive. Early functions compile while later ones are still downloading.
  3. Validate. Before anything runs, every function is checked: types match, jumps land in valid places, nothing reaches outside the sandbox. A bad module is rejected outright.
  4. Compile to machine code. The fast baseline compiler (V8's Liftoff) turns each instruction into machine code, so the app can start. Optimized code may be cached for your next visit.
  5. Instantiate. JavaScript hands over the imports. The engine creates linear memory, fills tables, runs the optional start function, and returns an instance with its exports.
  6. Call and tier up. JS calls exported functions like normal functions. Busy ones are quietly recompiled by TurboFan in the background and swapped in.

Why streaming matters

Compiling doesn't wait for the download to finish. The two run side by side, like reading a book while it's still being printed.

The JavaScript side

This is all the JavaScript you need to load a module and call it.

main.js
const imports = {                          1
  env: { log: (n) => console.log("from wasm:", n) }
};

const { instance } =                       2
  await WebAssembly.instantiateStreaming(
    fetch("add.wasm"), imports
  );

console.log(instance.exports.add(2, 3));   3
// 5
  1. The imports: tools JS lends the module. Here, a log function it may call.
  2. Fetch, stream-compile, validate and instantiate, all in one call. You get back a ready instance.
  3. Call an export like any JS function. Numbers go in, a number comes out.

Passing a string: try it

Wasm functions only take and return numbers. So how does it read a word? JavaScript writes the bytes into Wasm's linear memory, then passes just two numbers: where the bytes start and how many there are.

Real apps rarely write this by hand: Emscripten and Rust's wasm-bindgen generate this glue code for you.

The validator's checklist

Before any code runs:
  • every instruction gets values of the right type
  • every jump lands on a valid target
  • every function call matches its signature
  • only declared memory, tables and globals are used
Why so strict?

Checking everything up front, in one fast pass, means the engine can trust the code afterwards. Combined with bounds checks on memory, it's a big reason Wasm from any website is safe to run.

Remember
  • Fetch → stream-compile → validate → machine code → instantiate → call.
  • instantiateStreaming overlaps downloading and compiling.
  • Strings and images travel through linear memory: JS writes the bytes, Wasm gets an address and a length.
