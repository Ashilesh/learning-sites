Chapter 1

Wasm in plain words

WebAssembly is a universal "machine language" for the web. You write a program in almost any language, translate it once into a small .wasm file, and every modern browser can run it fast and safely.

The kitchen analogy

Think of your browser as a restaurant kitchen, and the program as a dish to cook.

What it is, in one minute

1

A binary format

Compact bytes, not human-readable text. A readable text form, .wat, exists for learning and debugging.

2

A compilation target

You rarely write Wasm by hand. Compilers for C/C++ (Emscripten, Clang), Rust, Go, C#, Kotlin, Zig and others produce it.

3

A sandbox

Wasm runs in a box with its own private memory. It touches the outside world only through functions it is explicitly given.

4

JavaScript's partner

JS stays in charge of the page. Wasm does the heavy lifting: image filters, physics, video, compression, games, AI.

5

Not only browsers

The same format runs on servers, edge networks, plugins and small devices, through runtimes like Wasmtime and WasmEdge.

Write once, run (almost) anywhere

One .wasm file works in every major browser and on every operating system, because the browser turns it into the right machine code for your computer.

A team, not a replacement

JavaScript is great at
  • the page: buttons, text, layout (the DOM)
  • reacting to clicks, typing and scrolling
  • talking to the network and browser features
  • glue: loading Wasm and passing it data
WebAssembly is great at
  • heavy maths: physics, simulations, 3D
  • images, audio and video processing
  • compression, encryption, databases
  • reusing big C/C++/Rust libraries as they are
Remember
  • Wasm is a compact, binary instruction format that compilers produce from many languages.
  • It runs fast because there's little left to interpret, and safely because it lives in a sandbox.
  • JavaScript runs the page; Wasm does the heavy lifting. They work as a team.
