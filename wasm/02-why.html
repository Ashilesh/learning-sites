Chapter 2

Why Wasm exists

JavaScript is fast today, but it was never designed to be a fast, predictable target for heavy, low-level work written in other languages. Wasm fills that gap.

Four things JavaScript struggles with

Warm-up time

The engine must read the source text, then watch the code run before it can make it fast. Big apps pay this on every load.

Unpredictable speed

Types can change any time (x is a number, then a string). The optimizer guesses; a wrong guess throws fast code away.

No memory control

Games, codecs and simulations want tightly packed rows of numbers, not objects shuffled around by a garbage collector.

Reusing old code

Decades of C, C++ and Rust libraries (SQLite, FFmpeg, OpenCV, physics engines) couldn't run in a browser without a rewrite.

The start-up race

Imagine a big app starting up. JavaScript speeds up in stages as the engine learns about the code, and can stumble when a guess turns out wrong. Wasm declares everything up front, so it reaches a steady speed early.

An illustrative sketch, not a benchmark. Real numbers depend on the app, the browser and the device, and well-optimized JavaScript can be just as fast once warmed up.

How we got here

  1. 2011
    Native Client (NaCl)Google runs native code inside Chrome. Clever, but Chrome only.
  2. 2013
    asm.jsMozilla's strict, easy-to-optimize subset of JavaScript that compilers can target. The direct ancestor of Wasm.
  3. 2015
    WebAssembly announcedAll the big browser makers agree on one shared binary format.
  4. 2017
    Wasm 1.0 shipsThe "MVP" (minimum viable product) lands in Chrome, Firefox, Safari and Edge.
  5. 2019
    An official web standardThe core spec becomes a W3C Recommendation on 5 Dec 2019.
  6. 2024
    WASI 0.2Standard system interfaces for Wasm outside the browser (25 Jan 2024).
  7. 2025
    Wasm 3.0The new live standard: garbage collection, 64-bit memory, exceptions, tail calls and more (17 Sep 2025).
  8. 2026
    WASI 0.3Ratified with native async for components (11 Jun 2026).

Spotted in the wild

Remember
  • JS has to warm up and guess types; Wasm starts with everything declared.
  • Wasm lets decades of existing C, C++ and Rust code run on the web.
  • It grew from NaCl and asm.js, shipped in 2017, and reached Wasm 3.0 in 2025.
