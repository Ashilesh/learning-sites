Chapter 10

Limitations

Most of Wasm's limits come from the same choice that makes it safe: it can only reach the outside world through doors JavaScript opens for it.

One choice, many limits

The sandbox rule "Only touch what you're handed, and nothing else."
no direct DOM no direct GPU costly JS ↔ Wasm trips awkward threads no wide SIMD or NPU

Others come from Wasm being young: memory that won't shrink, big downloads, harder debugging.

Eleven limits, flipped

Front: the limit. Back: why it exists, and what people do today.

No direct DOM or Web API accesswhy? tap ↻

Why: Web APIs are built for JavaScript objects; Wasm only sees numbers and opaque references.

Today: generated JS glue (wasm-bindgen, Emscripten). Keep UI in JS, computing in Wasm.

Crossing the JS ↔ Wasm border costs timewhy? tap ↻

Why: each call converts values; strings and objects get copied into linear memory.

Today: batch work into a few big calls, use JS string built-ins, share memory views instead of copying.

No direct GPU accesswhy? tap ↻

Why: security. A page must never talk to the graphics driver directly.

Today: WebGL or WebGPU through JS; batch draw calls and upload data in bulk.

Threads are awkwardwhy? tap ↻

Why: they need Web Workers + SharedArrayBuffer + isolation headers, and GC objects, tables and functions can't be shared yet.

Today: set COOP/COEP headers; message-pass between workers; Emscripten pthreads.

Waiting on async web APIswhy? tap ↻

Why: C, C++ and Rust code expects calls that block; the web is built on promises.

Today: JSPI (shipping in Chrome, phase 5), or Asyncify (bigger, slower code).

Memory grows but never shrinkswhy? tap ↻

Why: linear memory is one block; giving pages back would break addresses.

Today: reuse buffers; restart the instance or worker to get memory back.

A memory ceilingwhy? tap ↻

Why: 32-bit addresses reach 4 GiB; 64-bit memory is capped at 16 GiB on the web.

Today: Memory64 for big data; stream data instead of loading it all.

Big downloadswhy? tap ↻

Why: whole language runtimes and standard libraries get compiled in.

Today: wasm-opt, link-time optimization, lazy-loaded modules, Brotli compression.

Harder to debug than JSwhy? tap ↻

Why: it's binary code; mapping it back to your source needs extra debug info.

Today: DWARF debug info + Chrome's C/C++ DevTools extension; source maps.

Languages don't mix easily (yet)why? tap ↻

Why: each toolchain invents its own way to pass strings, lists and records.

Today: the Component Model and WIT interfaces, mostly outside the browser so far.

Some hardware is out of reachwhy? tap ↻

Why: a portable instruction set: no 256/512-bit SIMD, no direct NPU access, predictable results required.

Today: 128-bit and relaxed SIMD; WebGPU for parallel maths; WebNN for AI chips.

Remember
  • The biggest limits (DOM, GPU, boundary cost) are the price of the sandbox.
  • Others (memory that won't shrink, size, debugging) are being worked on.
  • Rule of thumb today: UI in JavaScript, heavy computing in Wasm, few big calls between them.
