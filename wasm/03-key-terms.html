One module, many instances

A module is like a recipe card: you can hand copies to several chefs. Each chef (instance) gets their own countertop (memory), so they never mix up each other's ingredients.

Play with a stack machine

Wasm doesn't name its workspace slots like x = 2 + 3. It pushes values onto a stack and lets each instruction take what it needs from the top. Pick a program and step through it.

Reading a tiny module

Here's a whole module in the readable text format (.wat). It exports one function that adds two numbers.

add.wat
(module                         1
  (func $add (export "add")     2
    (param $a i32)
    (param $b i32)              3
    (result i32)
    local.get $a                4
    local.get $b
    i32.add))                   5
  1. Everything lives inside one module.
  2. A function named $add, exported to JavaScript as "add".
  3. Two inputs, both i32 (32-bit whole numbers). Every type is spelled out.
  4. Push a, then push b, onto the stack.
  5. i32.add pops both, pushes the sum. What's left on top is the result.
Remember
  • A module is the recipe; an instance is it running, with its own memory.
  • Linear memory is a private row of bytes; imports and exports are the only doors out.
  • Wasm is a stack machine: push values, then operate on the top of the stack.
