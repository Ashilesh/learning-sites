Chapter 8

Borrowed browser powers

Wasm has its own instructions for maths, memory and control flow. Almost everything else it borrows from the browser, nearly always through JavaScript.

Two toolboxes

built in Wasm's own toolbox
  • maths on whole and decimal numbers
  • linear memory (up to 4 GiB, or 16 GiB with 64-bit memory)
  • SIMD: 128-bit "do four sums at once" instructions
  • exceptions (try / throw)
  • garbage-collected structs and arrays (WasmGC)
  • atomic instructions for shared memory
borrowed asked from JavaScript
  • the page: document, events, CSS
  • network: fetch, WebSocket, WebTransport
  • storage: IndexedDB, the Origin Private File System
  • graphics: Canvas, WebGL, WebGPU
  • sound and video: Web Audio, WebCodecs
  • threads themselves: Web Workers

Native exception handling in Wasm 3.0, and it works together with JS exceptions.

Atomics are built in; the threads are Web Workers sharing a SharedArrayBuffer. The page needs COOP/COEP headers.

How threads work

In plain words

Each Web Worker runs its own copy of the module, but they all point at one shared memory. Atomic instructions stop them from scribbling over each other.

For safety, the page must be "cross-origin isolated" by sending two headers: Cross-Origin-Opener-Policy and Cross-Origin-Embedder-Policy.

Remember
  • Built in: maths, memory, SIMD, exceptions, GC, atomics.
  • Borrowed through JS: the page, network, storage, graphics, audio, workers.
  • Threads = Web Workers sharing one memory, on a cross-origin isolated page.
