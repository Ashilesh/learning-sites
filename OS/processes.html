Chapter 3

Processes & Scheduling 🏃

Your computer runs hundreds of programs "at the same time" on just a few CPU cores. How? By being an amazing juggler. 🤹

🧸 In one sentence: a program is a recipe book 📖, a process is someone actually cooking that recipe 👩‍🍳, a thread is an extra cook in the same kitchen, and the scheduler decides who gets the stove next. 🔥

📖 Program vs process

🧸 Kid version

The recipe for pancakes sits on the shelf doing nothing — that's a program (a file on disk). When mom and dad both start cooking pancakes from the same recipe, that's two processes: same recipe, separate pans, separate progress. 🥞🥞

🪪 What Linux remembers about each process

For every process, the kernel keeps an ID card called the Process Control Block. In Linux it's a C struct named task_struct (in include/linux/sched.h) — it has hundreds of fields!

🔢 IDs

PID, parent PID, user (UID), group

🚦 State

running, sleeping, stopped, zombie…

🧮 Memory map

Where its code, heap and stack live (mm_struct)

📂 Open files

File descriptor table (0, 1, 2, …)

⏱️ Scheduling

Priority, nice value, CPU time used, vruntime

💾 Saved CPU state

Registers, program counter, stack pointer (for context switches)

📨 Signals

Pending & blocked signals, handlers

🔐 Security

Credentials, capabilities, namespaces, cgroup

🚦 The life of a process

A process moves between states. The letters are what ps and top show in their STAT column.

🧬 Lab: how new processes are born

🧸 Cell division!

A new process is made by copying an existing one, like a cell splitting in two — that's fork(). Then the copy can become a different program — that's exec(). When it's done it calls exit(), and the parent collects its "report card" with wait().

🐧 Exactly how your shell runs ls
pid_t pid = fork();          // now there are two of us
if (pid == 0) {              // I'm the child
    execvp("ls", argv);      // become "ls"
} else {                     // I'm the parent (bash)
    waitpid(pid, &status, 0);// wait for the child
}

🧵 Threads: many cooks, one kitchen

✅ Why threads?

Cheap to create, share memory instantly, use many CPU cores for one job (a game: physics, sound and graphics in parallel).

⚠️ The catch

Shared memory = they can trip over each other (race conditions). One crashing thread crashes the whole process. → Chapter 8

🐧 Linux secret

Linux doesn't really distinguish! Both are "tasks" made by clone(). A thread is a task that shares memory (CLONE_VM), files and signal handlers with its siblings.

🔁 The context switch

How does one CPU core run many processes? It saves one's "bookmark" and loads another's — hundreds of times per second.

🔬 Deep dive: what does a switch cost?

The switch itself is a few microseconds: save registers, switch the kernel stack, maybe switch page tables. The hidden cost is bigger: the new process finds the CPU caches and TLB full of the old process's data, so it runs slower for a while. That's why schedulers don't switch too often, and why pinning busy work to a core (taskset) can help.

$ grep ctxt /proc/stat
ctxt 482193022          # context switches since boot
$ pidstat -w 1          # per-process switches per second (sysstat)

⚖️ How Linux really schedules: fairness

Linux's normal scheduler doesn't use any of the textbook rules above directly. It tries to be fair: every task should get its share of CPU, weighted by its nice value.

🧸 The fairness race

Every task has a virtual stopwatch (vruntime). The scheduler always runs the task whose stopwatch shows the least time. Important tasks have slow stopwatches ⏱️🐢, so they get picked more often!

🐧 Under the hood

From 2007, this was CFS (Completely Fair Scheduler), keeping tasks sorted by vruntime in a red-black tree and picking the leftmost. Since kernel 6.6 (2023) it's EEVDF, which adds "virtual deadlines" so short, latency-sensitive tasks get to run sooner. Same fairness idea.

💡 Load average, explained

The three numbers are the average number of tasks running or waiting to run (plus those stuck in disk waits) over 1, 5 and 15 minutes. On an 8-core machine, a load of 8 means "fully busy"; 16 means "a queue is forming".
