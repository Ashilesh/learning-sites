✅ Best practices

🧑‍💻 Using & running Linux

  • Work as a normal user; sudo only the command that needs it.
  • Update often (apt upgrade / dnf upgrade); reboot for kernel fixes.
  • Read available in free -h, not free — cache is good!
  • Know your load average vs CPU count (nproc).
  • Run services as systemd units with limits: MemoryMax=, CPUQuota=, Restart=on-failure.
  • Check logs first: journalctl -b -p warning, dmesg.
  • Watch disks: df -h and inodes df -i; keep free space.
  • Keep a little swap (or zram) to soften memory spikes.
  • Back up with the 3-2-1 rule (3 copies, 2 media, 1 offsite) — and test restores.
  • Containers: set limits, run as non-root, pin image versions.

👩‍🔧 Writing programs that play nice with the OS

  • Always check system call results and errno — disks fill up, networks fail.
  • Close what you open; use O_CLOEXEC so file descriptors don't leak into children.
  • Never busy-wait. Block, or use epoll / io_uring for many connections.
  • Keep critical sections tiny; always take locks in the same order.
  • Processes for isolation, threads for shared-memory speed.
  • Handle SIGTERM: finish work, flush, exit cleanly.
  • fsync() when data must survive a crash (and the directory for new files).
  • Batch I/O: fewer big reads/writes beat many tiny ones.
  • Drop privileges early; ask for capabilities, not root.
  • Measure before optimizing: strace, perf, bpftrace.
