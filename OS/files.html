Chapter 6

Everything is a File 📁

Linux's biggest, simplest idea: almost everything — documents, keyboards, disks, running programs, network settings — shows up as a file. Learn to read and write files, and you can talk to the whole computer.

🧸 In one sentence: in Linux, a "file" is any box with a name that you can open, read from, write to, and close — even if what's inside the box is your keyboard! ⌨️📦

✨ Tap anything — it's a file!

Each button is a part of the computer. Tap it to see its Linux file path and a real command that uses it.

🐧 Why is this genius?

Because the same four system calls — open(), read(), write(), close() — work on everything, tiny tools like cat, echo and grep can work with disks, devices, processes and settings without knowing anything special about them. Fewer special cases = simpler, more powerful system.

🏠 The Linux house: folder structure

There's no C:\ in Linux. Everything lives in one tree starting at /. Think of it as a house — click the rooms!

🔬 Deep dive: why /bin and /usr/bin are the same thing now

In the 1970s, the first disk was tiny, so essential tools went in /bin and the rest in /usr/bin on a second disk. That split stopped making sense. Most modern distros did the /usr merge: /bin, /sbin and /lib are now just symlinks into /usr.

$ ls -l / | grep -- '->'
lrwxrwxrwx   1 root root     7 Apr 22 bin -> usr/bin
lrwxrwxrwx   1 root root     7 Apr 22 lib -> usr/lib
lrwxrwxrwx   1 root root     8 Apr 22 sbin -> usr/sbin

🎟️ File descriptors: your ticket numbers

🧸 Coat-check tickets

When a program opens a file, the kernel keeps the real thing and hands back a little ticket number — a file descriptor. Later the program just says "read from ticket 3". Every program starts with three tickets already: 0 = keyboard in, 1 = screen out, 2 = errors out.

$ ls -l /proc/self/fd
lrwx------ 0 -> /dev/pts/0
lrwx------ 1 -> /dev/pts/0
lrwx------ 2 -> /dev/pts/0
lr-x------ 3 -> /proc/48211/fd
$ ulimit -n          # max open files per process
1024

🔀 Redirection = swapping the tickets

$ ls > list.txt            # fd 1 → list.txt
$ ls /nope 2> errors.txt   # fd 2 → errors.txt
$ make > build.log 2>&1    # fd 2 → wherever fd 1 goes
$ sort < names.txt         # fd 0 ← names.txt
$ ls /etc | grep ssh | wc -l   # pipes connect 1 → 0
3
$ echo "hi" > /dev/null        # throw output away
$ cat /dev/urandom | head -c 4 | xxd
00000000: 9f3a c1e7

🧾 Inodes: a file's real identity

🧸 Name tag vs the actual kid

A file's name is just a name tag. The real "kid" is the inode — a numbered record that knows who owns the file, its size, when it changed, and where its data blocks are on the disk. A folder is just a list of name tags pointing to inode numbers. One kid can wear two name tags (a hard link)!

$ ls -i notes.txt
1311 notes.txt
$ stat notes.txt
  File: notes.txt
  Size: 13          Blocks: 8      IO Block: 4096  regular file
Device: 259,2      Inode: 1311   Links: 1
Access: (0644/-rw-r--r--)  Uid: (1000/kid)  Gid: (1000/kid)
Modify: 2026-11-27 10:15:02

🔗 Hard link

A second name for the same inode. Delete either name: the data lives on until the link count hits 0. Can't cross file systems or point to folders.

↪️ Symbolic (soft) link

A tiny file that stores a path. Works across disks and for folders, but breaks ("dangling") if the target is removed or moved.

📒 Journaling: surviving a power cut

🧸 Write the to-do list first

Before cleaning your room, you write on a notepad: "1. move books to shelf 2. put toys in box". If mom calls you mid-way, you can look at the notepad and finish (or undo) cleanly. A journal is that notepad for the file system.

🐧 ext4's three modes
  • ordered (default): file data is written before the metadata is committed to the journal.
  • journal: data AND metadata go through the journal (safest, slower).
  • writeback: only metadata journaled (fastest, old data may show up after a crash).

Copy-on-write file systems (btrfs, ZFS) take a different path: they never overwrite in place — they write new blocks, then flip a pointer. 🔀
