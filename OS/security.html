Chapter 9

Users & Security 🔐

Many people and programs share one computer. The OS decides who may read, change or run what — and builds walls so that one bad program can't take over everything.

🧸 In one sentence: every file has a lock with three keyholes — one for its owner, one for their group, one for everyone else — and each keyhole can allow reading, writing and running. 🔑🔑🔑

👥 Users and groups

🧸 Name badges

Every person (and many programs) gets a user account with a number — the UID. Users can be in groups (like "teachers" or "art club") to share things. The super-boss is root, UID 0, who can do anything. 👑

$ id
uid=1000(kid) gid=1000(kid) groups=1000(kid),27(sudo),998(docker)
$ getent passwd root www-data
root:x:0:0:root:/root:/bin/bash
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin

Each line in /etc/passwd describes one user. Tap the pieces:

👆 Tap a part above.

👑 root (UID 0)

Bypasses all permission checks. Use it as little as possible!

🤖 system users (1–999)

For services like www-data, postgres. They usually can't log in (nologin shell).

🙋 humans (1000+)

Normal accounts. Passwords are stored hashed in /etc/shadow, readable only by root.

🧮 Lab: the permission calculator

presets:
0644-rw-r--r--

    📄 For files

    r read contents · w change contents · x run it as a program

    📁 For folders

    r list names · w create/delete/rename inside · x enter it (cd) and reach things inside

    🔢 The math

    r = 4, w = 2, x = 1. Add them per group: rwx = 7, r-x = 5, r-- = 4. So chmod 750 = rwx for owner, r-x for group, nothing for others.

    ✨ Special bits

    🦸

    setuid (4)

    The program runs as its owner, not as you. That's how passwd (owned by root) can update /etc/shadow for you.

    $ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 64152 /usr/bin/passwd
    👨‍👩‍👧

    setgid (2)

    On a folder: new files inherit the folder's group. Great for shared team folders.

    $ chmod g+s /srv/team
$ ls -ld /srv/team
drwxrwsr-x 2 root devs /srv/team
    📌

    sticky (1)

    On a shared folder: you can only delete your own files. That's why everyone can use /tmp safely.

    $ ls -ld /tmp
drwxrwxrwt 18 root root /tmp
    ⚠️ setuid is powerful

    A bug in a setuid-root program means an attacker can become root. Modern Linux prefers giving programs just the specific capabilities they need instead (below).

    🦸 sudo: borrowing the crown for a moment

    $ apt install cowsay
E: Could not open lock file /var/lib/dpkg/lock - open (13: Permission denied)
$ sudo apt install cowsay
[sudo] password for kid:
$ sudo -l | tail -1      # what am I allowed to do?
    (ALL : ALL) ALL

    🧅 Layers of defense

    Good security is an onion: if one layer fails, the next still protects you. Click a layer.

    🎫 Capabilities: root, sliced into pieces

    🧸 A key ring instead of a master key

    Instead of giving a program the master key to the whole building (root), Linux can hand it just the one key it needs — e.g. "may open ports below 1024" — and nothing else.

    CAP_NET_BIND_SERVICE

    use ports below 1024 (a web server on port 80)

    CAP_NET_ADMIN

    change network settings, firewall

    CAP_SYS_TIME

    set the system clock

    CAP_KILL

    send signals to anyone's processes

    CAP_CHOWN

    change file owners

    CAP_SYS_PTRACE

    debug other processes

    CAP_SYS_ADMIN

    the "new root" — far too many powers in one. Avoid!

    ~40 in total

    man 7 capabilities

    $ getcap /usr/bin/ping
/usr/bin/ping cap_net_raw=ep
$ sudo setcap cap_net_bind_service=+ep ./my-web-server   # port 80 without root!
$ docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE nginx

    🎰 Lab: ASLR — hide and seek with addresses

    🧸 Moving the treasure

    Attackers often need to know where things are in memory. So every time a program starts, Linux puts its stack, heap and libraries at random places. Like a hide-and-seek game where the hiding spots change every round. 🙈

    🎰 ASLR

    Random addresses. /proc/sys/kernel/randomize_va_space = 2

    🚫 NX bit

    Memory is either writable OR executable, never both. Injected data can't run as code.

    🐤 Stack canaries

    A secret value before the return address; if it changes, the program stops before damage.

    👑 KASLR & more

    The kernel randomizes itself too, and refuses to run user memory in kernel mode (SMEP/SMAP).
