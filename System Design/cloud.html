☸️Kubernetes: the robot manager for containers

You tell Kubernetes what you want (“run 4 copies of my app”). It keeps checking reality and fixes any difference — forever. That's called a control loop.

👶 Like you're 5

A teacher who must always have 4 kids on the field. If one gets tired, the teacher sends in another — without being asked.

🖥️ Node — a machine in the cluster
🫛 Pod — one running copy of your container(s)
📋 Deployment — “keep N pods of version X”
🔌 Service — one stable address in front of the pods
📈 Autoscaler — changes N based on load
🔐 ConfigMap / Secret — settings & passwords
6.3

🌍Regions, availability zones & edge locations

One region = several zones (separate buildings, power & cooling) a few miles apart

🗺️ Region

A geographic area (e.g. “US-East”, “Europe-West”). Pick one close to your users and allowed by data laws.

🏢 Availability Zone (AZ)

An independent data center inside a region. Fires, floods or power cuts usually hit only one zone — so run copies in at least two.

📍 Edge location

Small sites in hundreds of cities for CDN caching and DNS — closest to users.

🧠 Rule of thumb

Multi-AZ = survive a building failure (cheap, do it always). Multi-region = survive a regional disaster (costly, do it when downtime is very expensive).

6.4

📖DNS deep dive: finding pizza.com

Turning a name into an address is a little treasure hunt across the world's DNS servers — then the answer is cached so next time is instant.

📇 Common DNS records

Aname → IPv4 address (pizza.com → 93.184.216.34)
AAAAname → IPv6 address
CNAMEnickname → another name (www → pizza.com)
MXwhere email for the domain goes
NSwhich servers are in charge of the domain
TXTnotes for verification & email security
⏰ TTL — every answer says how long it may be cached (e.g. 300 s). Low TTL = fast changes; high TTL = fewer lookups.
🧭 GeoDNS / latency routing — answer with the closest healthy region's address.
⚠️ Gotcha — after you change a record, old answers live on in caches until their TTL runs out. Lower the TTL before a migration.

🚗 HTTP/1.1

One file at a time per connection, so browsers open ~6 connections. Each needs its own handshake. A slow file blocks the ones behind it.

🛣️ HTTP/2

One connection, many files at once (multiplexing). But it runs on TCP: one lost packet pauses every file (head-of-line blocking).

✈️ HTTP/3 (QUIC)

Runs on UDP with its own reliability per stream. A lost packet only pauses its own file, and the handshake is faster.

🔒 TLS handshake

“Hello!” → server shows its certificate (ID card) → both agree on a secret key → everything after is encrypted. TLS 1.3 does it in one round trip.

6.6

🏭CI/CD: a factory line for code

Continuous Integration checks every change automatically. Continuous Delivery ships it safely, many times a day.

📜 Infrastructure as Code — servers, networks & databases described in files (e.g. Terraform), reviewed like code, recreated with one command.
🐤 Progressive delivery — canary first, watch metrics, auto-rollback if errors rise.
🧪 Test pyramid — many fast unit tests, fewer integration tests, a few end-to-end tests.
6.7

💰Cloud costs (the bill is a design input!)

🧾 Monthly bill estimator

Example prices only (≈ $0.10/server-hour, $23/TB-month storage, $80/TB egress) — real prices vary by provider and size.

📤 Egress is sneaky — moving data out of the cloud (to users or other clouds) often costs more than storing it. CDNs help.
🧊 Storage tiers — hot (fast, pricey) → cool → archive (cheap, slow to fetch). Move old data down automatically.
📉 Right-size & autoscale — most servers idle at 10–20% CPU. Smaller machines + autoscaling save a lot.
🎯 Each extra 9 costs more — going from 99.9% to 99.99% can mean another region and double the bill. Spend where downtime hurts.
