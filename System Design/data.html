🧠 How to choose

Default to SQL (e.g. PostgreSQL) — it handles more than people think. Choose NoSQL when you have massive scale with simple access patterns (look up by key), very flexible data, or need writes spread across many machines/regions.

5.4

🏦Transactions & ACID: moving money safely

Ana sends Bo $10. Two steps: take $10 from Ana, give $10 to Bo. What if the power cuts in between? 😱 ACID saves us:

⚛️ Atomic

All steps happen, or none. No “money vanished” halfway.

✅ Consistent

Rules always hold (balance ≥ 0, total money unchanged).

🙈 Isolated

Others can't peek at half-done work. Two transfers don't trip over each other.

💾 Durable

Once it says “done”, it stays done — even after a crash.

🌊 BASE: the relaxed cousin

Basically Available, Soft state, Eventually consistent. Many NoSQL systems choose this: always answer quickly, and let copies catch up a moment later. Fine for “likes”, not for bank balances.

5.5

📠Replication: keep copies of your data

Copies on several machines give you safety (one dies, others live) and speed (spread out the reads). But copies take time to sync…

🔒 Synchronous

Leader waits for followers to confirm. No data loss, but slower and stuck if a follower is down.

📨 Asynchronous

Leader answers immediately, followers catch up. Fast, but recent writes can be lost if the leader dies.

👑 Leader–follower

One writer, many readers. Simple and most common.

👑👑 Multi-leader

Writers in each region. Fast local writes, but conflicts must be resolved.

🤝 Leaderless

Write to several nodes, read from several (quorums). Dynamo/Cassandra style.

5.6

🍕Sharding: slice the data like a pizza

When data is too big (or too busy) for one machine, split it into shards. Each shard holds a slice and lives on its own server.

👶 Like you're 5

One library is overflowing. Build 3 libraries: names A–H go to library 1, I–P to library 2, Q–Z to library 3. Each one is smaller and quicker!

A router uses the shard key to find the right slice

📏 Range sharding

A–H, I–P, Q–Z or by date. Range queries are easy, but some ranges get crowded (hot spots).

#️⃣ Hash sharding

hash(user_id) % N. Spreads evenly, but range queries hit every shard.

📒 Directory

A lookup table says where each key lives. Flexible; the directory must be fast and safe.

🌍 Geo

EU users → EU shard. Fast & helps with data laws; uneven sizes.

⚠️ Sharding pains

Cross-shard JOINs and transactions get hard, re-sharding moves lots of data, and a bad shard key (like a celebrity's ID) creates a hot shard. Pick a key with many values that spreads load evenly — and shard only when you must.

5.7

💍Consistent hashing — the magic ring

With hash(key) % N, adding one server moves almost every key. Consistent hashing puts servers and keys on a ring: each key belongs to the next server clockwise. Add or remove a server and only its neighbors' keys move!

5.8

🔺The CAP theorem — cut the cable!

A distributed system can't promise all three when the network breaks:

  • Consistency — everyone reads the latest value
  • Availability — every request gets an answer
  • Partition tolerance — keeps going when the network splits

Networks will break, so P is a must. The real choice: during a split, refuse (CP) or answer with maybe-old data (AP)?

Mode:

Try: cut the cable, write, then read!

🧠 PACELC — the full story

If there's a Partition: choose A or C. Else (normal times): choose Latency or Consistency — because waiting for all copies to agree is slower even when nothing is broken.

🪜 The consistency ladder

💎 Strong / linearizableEveryone sees the latest write instantly, as if there's one copy. Bank balances, inventory counts. Slowest.
🔗 CausalReplies always show after the message they answer. Comments, chat threads.
🪞 Read-your-writesYou always see your own changes (others may lag). Profile edits.
🌊 EventualCopies agree… eventually (usually in ms–seconds). Like counts, view counts, feeds. Fastest.
5.9

🗳️Quorums: how many copies must agree?

Keep N copies. Wait for W to confirm each write and ask R when reading. If R + W > N, every read overlaps at least one copy with the latest write ✅.
