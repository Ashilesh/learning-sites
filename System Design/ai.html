12.1

🗺️What happens when you ask an AI assistant a question?

👶 Like you're 5

A super-smart friend (the model) answers questions, but a whole team helps: a door guard checks your ticket, a librarian finds the right pages, a safety buddy double-checks the answer, and a notebook remembers questions others already asked.

12.2

🧭Embeddings & vector search: a map of meaning

An embedding turns words, sentences or pictures into a long list of numbers. Things with similar meaning land close together on this “meaning map”.

“puppy” → [0.12, -0.83, 0.44, 0.07, -0.31, … 1,536 numbers]

Pick a search word. The vector database finds the nearest points — even if they share no letters!

🛣️ HNSW index

A multi-level “highway” graph: zoom across the map on fast roads, then walk local streets to the nearest points.

🏘️ IVF index

Group points into neighborhoods; only search the few neighborhoods closest to the query.

🎯 Approximate = fast

Exact search over billions of vectors is too slow; ANN indexes trade a tiny bit of accuracy for huge speed.

12.3

📚RAG: give the model an open book

Retrieval-Augmented Generation: before answering, look up the most relevant pieces of your documents and paste them into the prompt. The model answers from real, fresh facts — with sources.

✂️ Chunking — split docs into ~200–800 token pieces with a little overlap so ideas aren't cut in half.
🔀 Hybrid search — combine keyword search (exact names, codes) with vector search (meaning).
🥇 Re-ranking — fetch 50 candidates fast, then a smarter model picks the best 5.
🔐 Permissions — only retrieve chunks the user is allowed to see!
🔄 Freshness — re-index when docs change (events / CDC feed the indexer).
📎 Citations — return the sources so people can verify the answer.
12.4

⚡Serving large language models

Models write one token (≈ a word-piece) at a time on expensive GPUs. Two numbers matter: time to first token (feels responsive) and tokens per second (reading speed). Batching many users together boosts total throughput but slows each one a bit.

Illustrative numbers — real ones depend on hardware & model.

🧠 KV cache

The model remembers work done on earlier tokens so each new token is cheaper. Uses lots of GPU memory → limits batch size.

🚌 Continuous batching

Like a bus that lets passengers on and off at every stop instead of waiting for a full trip — keeps GPUs busy.

🔀 Model routing

Send easy questions to a small, cheap model and hard ones to a big model. Big savings, small quality loss.

📡 Streaming

Send tokens as they're made (Server-Sent Events). Users start reading in ~0.3 s instead of waiting 10 s.

🎟️ Quotas & rate limits

GPUs are scarce: limit tokens per minute per user/team, queue the rest, and shed load fairly.

🗜️ Quantization

Store model weights with fewer bits — smaller & faster, with a small accuracy cost.

12.5

💾Caching & cost control

🎯 Exact cache

Same question text → reuse the answer. Cheap, but rarely an exact match.

🧭 Semantic cache

“How do I reset my password?” ≈ “forgot my password” — similar embeddings (above a threshold) reuse an answer. Careful with personal data!

📌 Prompt / prefix caching

Long, repeated instructions at the start of prompts are processed once and reused — faster and cheaper.

💸 Token budgets

Cost ≈ (input tokens + output tokens) × price. Trim prompts, cap answer length, pick the smallest good model.
12.6

🛡️Safety, evaluation & monitoring

🚧 Guardrails

Check inputs and outputs: block harmful requests, strip personal data (PII), stop prompt-injection tricks hidden in documents, enforce the allowed topics.

🧪 Evaluation (“evals”)

A test set of questions with good answers, scored automatically (rules, or another model as judge) on every change — like unit tests for AI quality.

📊 Monitoring

Track latency, errors, cost per request, 👍/👎 feedback, and “I don't know” rates. Sample conversations for human review.

⚠️ Hallucinations

Models can sound confident and be wrong. Ground answers in retrieved sources, ask for citations, and allow “I don't know”.

🔁 Fallbacks

Timeouts on model calls, retry on another region or a smaller model, and a helpful non-AI fallback (search results, a human agent).

🧠 Treat prompts like code

Version them, review them, test them with evals, and roll them out with canaries — exactly like deployments.

12.7

🎯Recommendation systems: the funnel

“Videos you might like” can't score 100 million videos for every user in 100 ms. So it works like a funnel: cheap filters first, expensive smart models only on the few survivors.

🏪 Feature store

One place for facts about users & items (watch history, popularity) — same values for training (offline) and serving (online).

🧪 A/B testing

Show the new model to 5% of users, compare watch time / clicks against the old one, then decide.

🔄 Feedback loop

Clicks and skips flow back (via event streams) to retrain models daily — or update in near real time.

12.8

⚖️AI trade-offs

📚 RAG vs 🏋️ fine-tuning

RAG = open-book exam: easy to update facts, shows sources. Fine-tuning = studying for the exam: teaches style and skills, but facts get stale and retraining costs money. Often: RAG for knowledge, fine-tune for behavior.

🐘 Big vs 🐭 small model

Big = smarter but slower and pricier. Small = fast and cheap. Route by difficulty, and measure with evals before switching.

🔺 Quality · Latency · Cost

Pick two to optimize first. A support bot needs fast + cheap + “good enough”; a medical summary needs quality above all.

🛒 API vs 🏗️ self-host

Hosted APIs: zero ops, pay per token. Self-hosting open models: control and possibly cheaper at huge scale — but you run the GPUs.
